AutoPMX Help & User Guide

AutoPMX is a native macOS pharmacometrics modeling workbench. It integrates NONMEM / PsN execution, AI-assisted model building (via DuDu PMx), genetic algorithm optimization (parameter + structural search), and diagnostic visualization — all powered by local or cloud LLMs.

0a. Context Window Configuration (上下文窗口设置)

Most common cause of "LLM disconnected" or "model returned garbage": context window too small. Fix this FIRST before anything else.

0a.1 Why Context Window Matters

AutoPMX sends large prompts (rules + model files + diagnostics) that can reach 15,000–40,000 tokens. The default context window of many local LLM servers is too small, causing truncation, hallucination, or connection drops. You MUST configure it properly.

Why Context Window Matters

ScenarioEstimated TokensMin Window
Chat with DuDu (short Q&A)1,000–3,0004K
Model evaluation + diagnostics8,000–15,00016K
Generate next .mod (full rules + evidence)15,000–30,00032K
Long automation session (multi-turn context)20,000–40,00064K
Full PopPK rules (495 rules) + model + ext + lst30,000–60,000128K
Recommended minimum: 32K tokens. Below 16K, prompts are silently truncated — the LLM sees only partial rules, leading to incorrect model decisions. 128K is ideal for full automation with complete PopPK rules.

How to Set Context Window

⚠️ 90% of "LLM crashed / disconnected / garbage output" issues are caused by Ollama's default 2048-token context window.
AutoPMX sends 15K–60K tokens of rules + model files + diagnostics per request.
If context is too small: prompts silently truncated → rules lost → wrong model decisions.
You MUST configure this BEFORE running AutoPMX. It takes 30 seconds.
Ollama （最易出错 — 务必看完）

Ollama's default context is only 2048 tokens — 99% of AutoPMX requests will exceed this and silently fail. You MUST override it.

Recommended: 256K context (如果你的 Mac 有 ≥48GB 统一内存)：

# 1. 先停掉正在运行的 Ollama
ollama stop

# 2. 重新启动 — 256K 上下文 + 单线程 + 30分钟保活
OLLAMA_NUM_PARALLEL=1 \
OLLAMA_CONTEXT_LENGTH=262144 \
OLLAMA_KEEP_ALIVE=30m \
ollama serve

如果你只有 24GB 内存，使用 128K：

OLLAMA_NUM_PARALLEL=1 \
OLLAMA_CONTEXT_LENGTH=131072 \
OLLAMA_KEEP_ALIVE=30m \
ollama serve

Option B: 设置为永久环境变量

# macOS launchd 环境变量（重启后仍生效）
launchctl setenv OLLAMA_CONTEXT_LENGTH 262144
launchctl setenv OLLAMA_NUM_PARALLEL 1
launchctl setenv OLLAMA_KEEP_ALIVE 30m

Option C: 通过 Modelfile 固化到模型（最可靠）

ollama pull qwen2.5:32b

# 创建 Modelfile：
cat > /tmp/Modelfile << 'EOF'
FROM qwen2.5:32b
PARAMETER num_ctx 262144
PARAMETER keep_alive 30m
EOF

ollama create autopmx-qwen -f /tmp/Modelfile
# 然后在 AutoPMX 里把 Model 改成 autopmx-qwen

10. Automated Modeling (DuDu Auto)

DuDu Auto performs iterative stepwise PopPK model building driven by AI:

  1. Analyze Dataset — DuDu reads the CSV to detect administration route (IV Bolus, IV Infusion, Oral, or Mixed), subject count, dose levels, and available covariates.
  2. Generate Initial Model — Writes run001.mod using the appropriate PopPK template from the model library (1-compartment, route-matched ADVAN/TRANS).
  3. Run NONMEM — Executes the model. If it fails, DuDu reads the LST/FMSG error messages and repairs the control stream before trying again.
  4. Run Diagnostics — Only if the model runs successfully: GOF plots, VPC, individual plots, PK parameter extraction, and AI audits.
  5. AI Evaluation — DuDu evaluates diagnostics and decides to ACCEPT or REVISE based on FDA guidance criteria.
  6. Model Evolution — If REVISE, DuDu proposes exactly ONE change (add compartment, refine error model, add IIV, screen covariate) following strict escalation priority. Initial THETA values are inherited from the previous run's final estimates, with small upward perturbation — no arbitrary resets.
  7. Repeat — Up to 12 iterations, or until acceptance criteria are met.
  8. Best Model Selection — After completion, AutoPMX automatically selects the best model based on minimization success, covariance step, and OFV.

Automation Start Options

  • Fresh Start — Creates a new AutoModel project and begins from run001
  • Continue Latest — Resumes from the highest-numbered run in an existing AutoModel project
  • Selected Run — Continues from a specific run you choose
  • Dataset Picker — Choose which CSV file to use (only modeling datasets are shown; NONMEM table outputs are filtered out)

Model Evolution Priority

PassActionGuidance
1Refine structural model1-comp → 2-comp if GOF/VPC shows distribution phase misspecification
2Refine error modelCombined is default; simplify only if one component is unsupported
3Add IIVOne parameter at a time (CL first, then V); eta-shrinkage < 30%
4Screen covariatesWT on CL/V, then AGE, SEX, STUDY; OFV drop > 3.84
5BioavailabilityF1 only when both oral and IV data exist

Parameter Inheritance (稳定性策略)

每个新模型的初始参数值以上一轮输出估计值的向上取整为基础，不做任意重置：

  • 直接复制 — 同一含义参数取上一轮 final estimate，向上取整到 3 位有效数字
  • 微小扰动 — 新增参数取邻近参数的较小比例（如升级房室时 Q = CL × 0.5~0.8）
  • 禁止回退 — 不重置为任意整数（0.1、1、10、100），收敛值就是最好的起点
  • Omega/Sigma 继承 — 复制上一轮方差初始值，新 ETA 从 0.04~0.09 起步

Acceptance Criteria

  • GOF plots show no systematic bias
  • VPC prediction intervals capture observed data well
  • Parameter RSE < 50%, covariance step successful
  • No boundary estimates
  • CWRES centered around zero without trends
Important: If a NONMEM run fails, DuDu will not run diagnostics (GOF/VPC). Instead, it reads the LST error messages and attempts to fix the control stream before trying again. This saves time and avoids broken diagnostic plots.

12. SCM Covariate Screening (PsN)

SCM (Stepwise Covariate Model) is PsN's automated covariate selection tool. AutoPMX provides a user-friendly dialog to configure statistical thresholds and generates the PsN configuration file automatically via AI.

What SCM Does

  • Forward inclusion — tests each covariate one at a time, adding the most significant one if it passes the inclusion p-value threshold.
  • Backward elimination — after each forward step, checks if any included covariates can be removed at the stricter elimination threshold.
  • Outputs a final model with the optimal covariate combination and a step-by-step results table.

How to Launch SCM

  • Quick Actions Bar — Click the SCM button in the DuDu PMx chat panel's quick action bar.
  • Right-Click Menu — Right-click any model file (run*.mod) in the sidebar and select SCM. This opens the configuration dialog with that model pre-selected.
  • Chat with DuDu — Type "SCM" or "协变量筛选" in the chat; DuDu will open the configuration dialog.

Configuration Dialog

The SCM setup dialog lets you choose the base model, dataset, and statistical thresholds:

OptionDescription
Base ModelSelect which run*.mod to use as the starting model.
DatasetSelect the CSV data file (defaults to the project's dataset).
Forward Inclusion pp-value for adding covariates: 0.05 (ΔOFV > 3.84), 0.01 (ΔOFV > 6.63), or 0.001 (ΔOFV > 10.83).
Backward Elimination pp-value for removing covariates: 0.01 (ΔOFV > 6.63) or 0.001 (ΔOFV > 10.83). Must be ≤ forward p.
ΔOFV Reference: The χ² critical values (1 df) are p=0.05 → 3.84, p=0.01 → 6.63, p=0.001 → 10.83. A covariate must decrease OFV by more than this threshold to be included or retained.
Constraint: The backward elimination p-value cannot exceed the forward inclusion p-value. AutoPMX automatically clamps the backward value and filters invalid options from the picker. When p-forward equals p-backward, the search direction is set to forward-only.

How It Works

  1. AutoPMX copies the base model and dataset into a SCM_run{N}/ subdirectory.
  2. AI analyzes the model's $INPUT line and $PK block to detect covariates (AGE, WT, SEX, STUD) and parameters with IIV (CL, V, etc.).
  3. AutoPMX writes runCONCOV{N}.scm with the correct covariate lists, test relations, valid_states, and your chosen p-values.
  4. PsN scm is executed with the generated config file and base model.
  5. If the run fails, AutoPMX diagnoses the error and attempts to auto-fix the configuration (up to 2 retries) using PPK knowledge from previous sessions.

Results

After completion, results are available in:

  • SCM_run{N}/scm_results.csv — the main results table: each step's OFV change, covariate tested, and whether it was included or dropped.
  • SCM_run{N}/scm_final.xml — the final NONMEM control file with selected covariates.
  • SCM_run{N}/scm_log.txt — full PsN SCM execution log.
  • DuDu Chat Panel — summary of the run with exit status and p-value settings used.
Stop/Restart: While SCM is running, a red Stop button appears in the quick actions bar. Click it to terminate the running process at any time.

14. FAQ & Troubleshooting

Q: NONMEM reports "WARNING 23: $PK DOES NOT DEFINE A SCALE PARAMETER"

Your $PK block is missing S1=V/1000 (IV models) or S2=V/1000 (oral models). Add the scale parameter after defining V. AutoPMX's GA optimizer automatically injects this if missing.

Q: "ERROR IN TRANS2 ROUTINE: CL IS NEGATIVE"

NONMEM's gradient search is exploring negative parameter values for CL or V. The model still converges — these are intermediate search steps, not final estimates. Check the final parameter table in the .lst file.

Q: GA-optimized model won't run via right-click

GA###.mod files are now recognized correctly and the PsN command points to the right file.

Q: DuDu Auto keeps oscillating between two error models

Anti-oscillation rules now prevent DuDu from proposing toggling changes (e.g., remove IIV → re-add IIV) in consecutive iterations. If the model with fewer parameters has a working covariance step, it is preferred.

Q: "Covariance step failed / ERROR=134" — is the model still usable?

If minimization succeeded but covariance failed (R-matrix non-positive-definite), the parameter estimates are valid but their standard errors are unreliable. DuDu Auto now treats covariance failure as needing repair. Consider simplifying the model (remove one IIV term or simplify the error model).

Q: How do I switch between light and dark mode?

Settings → General → Appearance. Choose System, Light, or Dark.

Q: Where are the rule files?

All rules are configured in Settings → Rules. Rule sources belong in Settings.

About AutoPMX

AutoPMX (Auto Pharmacometrics) is a native macOS application for population pharmacokinetic (PopPK) and pharmacodynamic modeling. It wraps the industry-standard NONMEM and PsN tools with a modern SwiftUI interface, providing AI-assisted model building through local large language models.

Key Features:

  • One-click NONMEM execution with real-time terminal output
  • AI-driven automated model building (DuDu Auto) with up to 12 iterations of stepwise refinement
  • Parameter inheritance strategy — each iteration builds on previous final estimates with upward perturbation
  • Genetic algorithm optimization for initial estimates AND model structure
  • Integrated diagnostic visualization (GOF, VPC, individual plots, PK parameters)
  • Multi-provider LLM support (MLX, LM Studio, Ollama, OpenAI, Anthropic, Gemini, custom)
  • macOS-native design with dark mode, iMessage-style chat, and liquid glass effects
