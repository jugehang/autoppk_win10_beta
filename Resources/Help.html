AutoPMx is a native macOS pharmacometrics modeling workbench. It integrates NONMEM / PsN execution, AI-assisted model building (via DuDu PMx), genetic algorithm optimization (parameter + structural search), and diagnostic visualization — all powered by local or cloud LLMs. Currently, it is focused on AI-driven modeling exploration for human PK/PD of monoclonal antibody (mAb) therapeutics.AutoPMx 是一款 macOS 原生的定量药理学（群体药动学/药效学）建模工作台，集成了 NONMEM / PsN 执行、AI 辅助建模（通过 DuDu PMx）、遗传算法优化（参数 + 结构搜索）与诊断可视化——全部由本地或云端大模型驱动。目前重点针对单抗治疗药物的人体 PK/PD 建模做 AI 建模探索。

0.4 Context Window Configuration0.4 上下文窗口设置

Most common cause of "LLM disconnected" or "model returned garbage":「LLM 断开连接」或「模型输出乱码」最常见的原因： context window too small. Fix this FIRST before anything else.上下文窗口太小。请务必优先解决此问题。

Why Context Window Matters为什么上下文窗口很重要

AutoPMx sends large prompts (rules + model files + diagnostics) that can reach 15,000–40,000 tokens. The default context window of many local LLM servers is too small, causing truncation, hallucination, or connection drops. You MUST configure it properly.AutoPMx 每次请求会发送很大的提示词（规则 + 模型文件 + 诊断），可达 15,000–40,000 tokens。许多本地大模型服务的默认上下文窗口太小，会导致截断、幻觉或连接中断。必须正确配置。

  2. AI analyzes the model's $INPUT line and $PK block to detect covariates (AGE, WT, SEX, STUD) and parameters with IIV (CL, V, etc.).AI 分析模型的 $INPUT 行与 $PK 块，识别协变量（AGE、WT、SEX、STUD）及带 IIV 的参数（CL、V 等）。

  4. PsN scm is executed with the generated config file and base model.用生成的配置文件与基础模型执行 PsN scm。
  5. If the run fails, AutoPMx diagnoses the error and attempts to auto-fix the configuration (up to 2 retries) using PPK knowledge from previous sessions.若运行失败，AutoPMx 会诊断错误并尝试自动修复配置（最多 2 次重试），使用以往会话的 PPK 知识。

15. FAQ & Troubleshooting15. 常见问题与排错

Q: NONMEM reports "WARNING 23: $PK DOES NOT DEFINE A SCALE PARAMETER"问：NONMEM 报“WARNING 23: $PK DOES NOT DEFINE A SCALE PARAMETER”

Your $PK block is missing S1=V/1000 (IV models) or S2=V/1000 (oral models). Add the scale parameter after defining V. AutoPMx's GA optimizer automatically injects this if missing.你的 $PK 块缺少 S1=V/1000（静脉模型）或 S2=V/1000（口服模型）。定义 V 后补上比例参数。AutoPMx 的 GA 优化器会在缺失时自动注入。

Q: "ERROR IN TRANS2 ROUTINE: CL IS NEGATIVE"问：“ERROR IN TRANS2 ROUTINE: CL IS NEGATIVE”

NONMEM's gradient search is exploring negative parameter values for CL or V. The model still converges — these are intermediate search steps, not final estimates. Check the final parameter table in the .lst file.NONMEM 的梯度搜索正在探索 CL 或 V 的负值。模型仍会收敛——这些都是中间搜索步骤，并非最终估计。请查看 .lst 文件中的最终参数表。

Q: GA-optimized model won't run via right-click问：GA 优化模型右键无法运行

GA###.mod files are now recognized correctly and the PsN command points to the right file.GA###.mod 文件现已被正确识别，PsN 命令会指向正确的文件。

Q: DuDu Auto keeps oscillating between two error models问：DuDu Auto 在两个误差模型间反复横跳

Anti-oscillation rules now prevent DuDu from proposing toggling changes (e.g., remove IIV → re-add IIV) in consecutive iterations. If the model with fewer parameters has a working covariance step, it is preferred.防振荡规则现已阻止 DuDu 在连续迭代中提议来回切换的改动（如移除 IIV → 重新加回 IIV）。若参数更少的模型具有可用的协方差步，则优先选用。

Q: "Covariance step failed / ERROR=134" — is the model still usable?问：“协方差步失败 / ERROR=134”——模型还能用吗？

If minimization succeeded but covariance failed (R-matrix non-positive-definite), the parameter estimates are valid but their standard errors are unreliable. DuDu Auto now treats covariance failure as needing repair. Consider simplifying the model (remove one IIV term or simplify the error model).若最小化成功但协方差失败（R 矩阵非正定），参数估计有效但标准误不可靠。DuDu Auto 现会将协方差失败视为需要修复。可考虑简化模型（移除一个 IIV 项或简化误差模型）。

Q: How do I switch between light and dark mode?问：如何切换浅色/深色模式？

Settings → General → Appearance. Choose System, Light, or Dark.设置 → 通用 → 外观。选择 跟随系统、浅色或深色。
