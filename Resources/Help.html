AutoPMX Help & User Guide

AutoPMX is a native macOS pharmacometrics modeling workbench. It integrates NONMEM / PsN execution, AI-assisted model building (via DuDu PMx), genetic algorithm optimization (parameter + structural search), and diagnostic visualization — all powered by local or cloud LLMs.

1. Quick Start

  1. Set up LLM — Open Settings (⌘,) → LLM tab → choose MLX, LM Studio, Ollama, or add a cloud API provider. Click Test Connection to verify.
  2. Open a project — Use the toolbar to open an existing PopPK project, or create a new one from a run.
  3. Select a model — In the sidebar under "Models", click a run*.mod file to preview it. The Inspector shows parameter estimates if available.
  4. Run NONMEM — The PsN command is auto-populated in the Inspector. Click Run (⌘↩) to execute.
  5. Review results — Outputs, figures, and reports appear in the sidebar. Click any file to preview it — images, PDFs, DOCX, and HTML are rendered inline.

4. Sidebar & File Management

Sidebar Categories

Files are organized by type: Models, Outputs, Data, Figures, Reports, Scripts. Each category has its own collapsible section.

Context Menu Operations

Right-click any file to access:

  • Run NONMEM via PsN — Execute the selected .mod file
  • 🧮 GA Optimize — Run genetic algorithm to optimize THETA initial estimates
  • 🧮 GA Structure Search — Run hybrid GA to search model structure + THETA
  • Run GOF / VPC / Individual DV-Time — Generate diagnostic plots via R
  • Run Full Diagnostic Suite — GOF + VPC + individual + PK parameters + audits
  • Run Bootstrap / Run SCM — Advanced diagnostics
  • AI Evaluate This Model — Let DuDu PMx assess the model
  • Pin / Reveal in Finder / Move to Trash

Data vs Output Tables

AutoPMX automatically distinguishes modeling datasets (like NM_dat_new.csv) from NONMEM table outputs (like SDTAB001, PATAB001). Only modeling datasets appear in the DuDu Auto dataset picker. Table outputs are filtered out automatically.

8. PsN Command & NONMEM Execution

Default Command

execute run###.mod -model_dir_name

How it works

  1. Select a .mod file in the sidebar
  2. The PsN command auto-populates in the Inspector
  3. Edit if needed (e.g., add -retries=3 or change flags)
  4. Click Run or press ⌘↩
  5. Output appears in the Terminal panel
  6. New .lst, .ext, .cov files appear in the sidebar
Tip: If you right-click a GA-optimized model (GA###.mod), the PsN command automatically points to the correct file (execute GA###.mod), not the original run###.mod.

10. Automated Modeling (DuDu Auto)

DuDu Auto performs iterative stepwise PopPK model building driven by AI:

  1. Analyze Dataset — DuDu reads the CSV to detect administration route (IV Bolus, IV Infusion, Oral, or Mixed), subject count, dose levels, and available covariates.
  2. Generate Initial Model — Writes run001.mod using the appropriate PopPK template from the model library (1-compartment, route-matched ADVAN/TRANS).
  3. Run NONMEM — Executes the model. If it fails, DuDu reads the LST/FMSG error messages and repairs the control stream before trying again.
  4. Run Diagnostics — Only if the model runs successfully: GOF plots, VPC, individual plots, PK parameter extraction, and AI audits.
  5. AI Evaluation — DuDu evaluates diagnostics and decides to ACCEPT or REVISE based on FDA guidance criteria.
  6. Model Evolution — If REVISE, DuDu proposes exactly ONE change (add compartment, refine error model, add IIV, screen covariate) following strict escalation priority.
  7. Repeat — Up to 6 iterations, or until acceptance criteria are met.
  8. Best Model Selection — After completion, AutoPMX automatically selects the best model based on minimization success, covariance step, and OFV.

Automation Start Options

  • Fresh Start — Creates a new AutoModel project and begins from run001
  • Continue Latest — Resumes from the highest-numbered run in an existing AutoModel project
  • Selected Run — Continues from a specific run you choose
  • Dataset Picker — Choose which CSV file to use (only modeling datasets are shown; NONMEM table outputs are filtered out)

Model Evolution Priority

PassActionGuidance
1Refine structural model1-comp → 2-comp if GOF/VPC shows distribution phase misspecification
2Refine error modelCombined is default; simplify only if one component is unsupported
3Add IIVOne parameter at a time (CL first, then V); eta-shrinkage < 30%
4Screen covariatesWT on CL/V, then AGE, SEX, STUDY; OFV drop > 3.84
5BioavailabilityF1 only when both oral and IV data exist

Acceptance Criteria

  • GOF plots show no systematic bias
  • VPC prediction intervals capture observed data well
  • Parameter RSE < 50%, covariance step successful
  • No boundary estimates
  • CWRES centered around zero without trends
Important: If a NONMEM run fails, DuDu will not run diagnostics (GOF/VPC). Instead, it reads the LST error messages and attempts to fix the control stream before trying again. This saves time and avoids broken diagnostic plots.

11. GA Optimization

GA Initial Estimate Optimization

Entry: Right-click any run*.mod → 🧮 GA Optimize, or click the button in the Inspector's Parameter Estimates section.

What it does: Uses a built-in genetic algorithm to search for better THETA initial estimates. Each candidate is evaluated by running NONMEM. Fitness = −OFV + success bonus − diagnostic penalties. THETA values use (0, mid) format (lower bound fixed to 0).

ParameterDefaultDescription
Population size20Individuals per generation
Iterations10Number of generations
Elite ratio0.2Top fraction preserved each generation
Estimated runs200population × iterations

GA Structural Search

Entry: Right-click any run*.mod → 🧮 GA Structure Search, or click the button in the Inspector.

What it does: Hybrid GA that simultaneously searches model structure AND optimizes THETA values:

  • ADVAN / Compartments — 1-comp, 2-comp, or 3-comp (route-locked)
  • Error model — Proportional, combined, or additive
  • IIV — Which parameters get ETA terms + diagonal vs block OMEGA
  • Covariates — WT on CL/V, AGE, SEX, STUDY
ParameterDefaultDescription
Population size10Individuals per generation
Iterations5Number of generations
Elite ratio0.2Top fraction preserved
Estimated runs50population × iterations

Output

  • GA###.mod — Best model with optimal structure + THETA values
  • GA###_population.csv — All candidates with genes, values, and fitness for comparison

Prerequisites

  • Settings → Tools → NONMEM Path configured (nmfe)
  • Settings → Tools → Python Environment configured (Python 3.8+)
  • No external Python packages required (built-in GA engine)
  • Target run*.mod must have completed NONMEM successfully at least once

12. Settings

General

Appearance: Choose System (follow macOS), Light, or Dark mode.

LLM Providers

  • MLX (Apple Silicon) — Local models via MLX at http://127.0.0.1:8080/v1. Supports qwen3.6:35b-mlx and others.
  • LM Studio — Desktop LLM server at port 1234.
  • Ollama — Containerized local LLMs at port 11434.

Use the Toggle switch to activate a provider. Expand the row to edit URL, model name, and API key. Click Test Connection to verify.

Tools

  • NONMEM (nmfe) — Path to the NONMEM executable. Auto-detected from /opt/nm760 or which. Use Browse or Auto Detect.
  • PsN (execute) — Path to the PsN command. Auto-detected or browsable.
  • Python Environment — Detected from workspace .venv or system Python.
  • R (Rscript) — Path to Rscript for diagnostic plot generation.

13. FAQ & Troubleshooting

Q: NONMEM reports "WARNING 23: $PK DOES NOT DEFINE A SCALE PARAMETER"

Your $PK block is missing S1=V/1000 (IV models) or S2=V/1000 (oral models). Add the scale parameter after defining V. AutoPMX's GA optimizer automatically injects this if missing.

Q: "ERROR IN TRANS2 ROUTINE: CL IS NEGATIVE"

NONMEM's gradient search is exploring negative parameter values for CL or V. The model still converges — these are intermediate search steps, not final estimates. Check the final parameter table in the .lst file.

Q: GA-optimized model won't run via right-click

This is fixed in the current version. GA###.mod files are now recognized correctly and the PsN command points to the right file.

Q: DuDu Auto keeps oscillating between two error models

Anti-oscillation rules now prevent DuDu from proposing toggling changes (e.g., remove IIV → re-add IIV) in consecutive iterations. If the model with fewer parameters has a working covariance step, it is preferred.

Q: "Covariance step failed / ERROR=134" — is the model still usable?

If minimization succeeded but covariance failed (R-matrix non-positive-definite), the parameter estimates are valid but their standard errors are unreliable. DuDu Auto now treats covariance failure as needing repair. Consider simplifying the model (remove one IIV term or simplify the error model).

Q: How do I switch between light and dark mode?

Settings → General → Appearance. Choose System, Light, or Dark.

Q: Where are the rule files?

All rules are configured in Settings → Rules. The Rules JSON field in the Inspector has been removed to avoid confusion — rule sources belong in Settings.

About AutoPMX

AutoPMX (Auto Pharmacometrics) is a native macOS application for population pharmacokinetic (PopPK) and pharmacodynamic modeling. It wraps the industry-standard NONMEM and PsN tools with a modern SwiftUI interface, providing AI-assisted model building through local large language models.

Key Features:

  • One-click NONMEM execution with real-time terminal output
  • AI-driven automated model building (DuDu Auto) with up to 6 iterations of stepwise refinement
  • Genetic algorithm optimization for initial estimates AND model structure
  • Integrated diagnostic visualization (GOF, VPC, individual plots, PK parameters)
  • Multi-provider LLM support (MLX, LM Studio, Ollama, OpenAI, Anthropic, Gemini, custom)
  • macOS-native design with dark mode, iMessage-style chat, and liquid glass effects

Technology Stack: Swift 5.9+ · SwiftUI · macOS 13+ · NONMEM 7.4+ · PsN · Python 3.8+ · R 4+
